# ADR 002 — ORM Choice: Prisma

## Status

Accepted — September 2026

## Context

We need a Node.js ORM for Postgres that provides type-safe queries, schema migrations, and a generated client compatible with both NestJS (CJS) and Electron's Node.js runtime.

## Decision

**Prisma 7.10.0** (pinned — not 8.0.0-rc.15 which is the `latest` npm tag).

Key implementation choices:

- `prisma-client` generator with explicit `output`, `moduleFormat: "cjs"`, `generatedFileExtension: "ts"`, `importFileExtension: ""`.
- Uses **PrismaPg** driver adapter (`@prisma/adapter-pg` + `pg`) for Neon-compatible pooled connections.
- Schema lives in `packages/db/prisma/schema.prisma` with CLI config in `prisma.config.ts`.
- `prisma` CLI is run with `cwd = packages/db`; the migration runner (`runPendingMigrations`) spawns the CLI via `process.execPath` with retry logic.
- `prisma migrate deploy` is the idempotent production-safe migration apply command, called automatically on backend startup.

## Alternatives Considered

- **Drizzle ORM** — lighter, but less mature migration story; less ecosystem tooling.
- **TypeORM** — older, less type-safe, decorator-heavy, worse DX.
- **Prisma 8 (RC)** — acceptable risk/reward for production use; pinned to 7.10.0 which is fully stable.

## Consequences

- `packages/db` owns all database concerns; other packages never import Prisma directly.
- The generated client is committed in `packages/db/src/generated/` (gitignored for production, regenerated by `prisma generate`).
- `prisma` is a production dependency of `packages/db` (needed for `migrate deploy` in production containers).
